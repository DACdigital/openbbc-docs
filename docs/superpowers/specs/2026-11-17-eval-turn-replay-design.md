# eval-turn-replay — script-driven user turns and per-turn judging in `aikdm evaluate`

**Date:** 2026-11-17
**Status:** Draft — pending `/spec-review`
**Modularity attachment:** `docs/architecture/current/modularity/aikdm/eval-scoring/` (L2).
Also affects [`training-loop`](../../architecture/current/modularity/aikdm/training-loop/README.md),
which uses eval-scoring as its reward function (`aikdm train-agent` calls `run_eval`). Training
gets one small change: the teacher skips inconclusive judgments (Scope → In → 9).

**Origin:** handoff from the ai-sales-copilot project (an OpenBBC consumer), Item 1
("the eval user-simulator overruns sessions and the judge can't tell which reply a criterion was
for"). Item 2 of the same handoff (`client_context` on turns) is a separate spec. It plugs into
the `UserStep` this spec introduces (see Scope → In → 1).

**Design inspiration:** [langwatch/scenario](https://github.com/langwatch/scenario). In Scenario,
a test is an explicit **script** of steps:
- `user(text?)`: fixed text, or generated by the simulator;
- `agent(text?)`: the agent under test generates the reply, or a canned reply is injected;
- `judge(criteria)`: an inline checkpoint judged on the conversation so far;
- `succeed()` / `fail()`.

`max_turns` is only a safety net. Verdicts can be *inconclusive* as well as passed or failed. We
borrow the step-script model, inline per-turn checkpoints, judging the whole turn span, the
inconclusive verdict, and canned assistant history (our `reference` history mode). We do not
borrow goal-driven free-running simulation, deterministic code assertions, or record/replay
caching (see Scope → Out).

**Grounded against:** OpenBBC `main` @ `688a3c3`. Paths are relative to `aikdm/aikdm/` unless
stated otherwise.

## Business value / Why

Eval scores are the reward signal for `train-agent`. They are also the number a PL uses to decide
whether an agent version is better than its parent. Today that number is too noisy to decide
anything:

- **Sessions overrun the script.** In the consumer's datasets, a reference session with 1 user
  turn played 3 simulated turns, and one with 2 turns played 6. In the 6-turn case the scripted
  2nd turn was never sent, so the behaviour that turn was meant to test never happened.
- **Criteria are judged against the wrong reply.** A criterion written for reply #1 ("Is short
  (1–3 sentences) and ends with one pointed question") failed because of replies #2, #4 and #6,
  which only existed because of the overrun.
- **The noise hides real improvements.** The same unchanged agent version scored 0.79 in one eval
  and 0.88 as a training baseline minutes later. `train-agent` promotes only on a strictly higher
  score, so in 6 epochs across two agents nothing was promoted.

Root causes in code:

1. `eval/runner.py` `run_session` loops until the simulator LLM returns `stop=true`. The
   simulator prompt (`eval/simulator.py`) asks the model to *count* user turns inside a JSON
   blob, and small models miscount.
2. The hard cap is loose: `_count_user_turns(ref) + 4`.
3. The simulator prompt invites continuing. It says to "paraphrase it to fit the tested agent's
   most recent reply" and to "try to steer once", so when a reply ends in a question, the
   simulator answers it instead of sending the next scripted intent.
4. `eval/judge.py` `judge_transcript` explicitly ignores `message_id` and judges every criterion
   against the whole simulated transcript.
5. A latent bug found while grounding this spec: `eval/target.py` `target_turn` appends its own
   `{name, args, result, source}` tool-call entries into the caller's `conversation` list
   (line 115). On the next turn those entries are sent to LiteLLM as if they were OpenAI-format
   `tool_calls`, so multi-turn sessions with tool use replay malformed history.

Success is judged by:

- A reference session with N user turns always produces exactly N simulated user turns.
- Every criterion is judged on the turn it was written for, and nothing later in the
  conversation can affect that verdict.
- Run-to-run noise drops to where `train-agent` can see real improvements. The **target** (not a
  merge gate; see Acceptance 9) is a spread of at most 6 percentage points peak-to-peak (±3) in
  the score across 3 runs of an unchanged version on an unchanged CLOSED 10-session dataset with
  Haiku 4.5.

## Change level

**C2.** The cross-service result contract `eval-result-v1` (aikdm → open-bbcd) gains fields:
`Judgment.inconclusive` and two keys in `aikdm_meta`. Under `docs/conventions/api.md`, changing a
contract is C2 even when the change is additive.

The change is backward-compatible:
- open-bbcd stores both `judgments` and `aikdm_meta` as opaque JSONB (`types.EvalResult.AikdmMeta`
  is `json.RawMessage`, written as `$::jsonb` in `internal/repository/eval.go`).
- The BO's `parseJudgments` reads only `message_id`, `criterion`, `passed` and `reason`.
- So no open-bbcd change is needed.

Everything else is aikdm behaviour inside one L2. The input contract `eval-input-v1` is
unchanged, and there is no DB, event or security change. The new knobs are aikdm env settings,
not contract fields.

## Scope

### In scope

1. **Explicit step script.** Each reference session is compiled, before any LLM call, into a
   `Script`: an ordered list of steps, in a new module `eval/script.py`.

   ```python
   @dataclass(frozen=True)
   class UserStep:      # send user turn k
       turn: int                    # 1-based
       ref_message: InputMessage    # reference user message k
   @dataclass(frozen=True)
   class AgentStep:     # target generates turn k's reply span
       turn: int
       ref_span: list[InputMessage] # reference assistant/tool messages after user k
   @dataclass(frozen=True)
   class JudgeStep:     # checkpoint for turn k
       turn: int
       criteria: list[CriterionItem]  # (message_id, criterion text)
   Step = UserStep | AgentStep | JudgeStep
   ```

   `compile_script(session) -> Script` builds the steps as follows:
   - The script compiles from the root transcript only. That is the only transcript the export
     carries: it returns `409` for versions with the agent tool, and judges score the root
     transcript only, per `ddd/contexts/evaluation.md`.
   - Turn *k* is reference user message *k* plus every following message up to, but not
     including, reference user message *k+1*.
   - For each turn the script emits `UserStep(k)` then `AgentStep(k)`, then `JudgeStep(k)` if
     turn *k* has criteria.
   - Assistant messages before the first user message belong to turn 1.
   - `role: tool` messages belong to their span only.

   **Criteria routing.** A criterion goes to the turn whose span contains its `message_id`. That
   includes intermediate tool-calling assistant messages.
   - If the id belongs to a user or tool message, or is not in the transcript, the criterion is
     **unmapped**. It goes to the **last** turn and is **judged normally** there, so it can pass
     or fail and is never inconclusive for being unmapped. Its judgment `reason` is prefixed
     with `"[unmapped message_id <id>, judged against last turn] "`.
   - Criteria are never dropped.
   - Within a turn, criteria are ordered by the position of their `message_id` in the reference
     transcript, then by item index. This is deterministic even though open-bbcd's export builds
     `criteria` from a Go map, whose order varies.

   A reference transcript with zero user messages compiles to an empty script. Every criterion
   then becomes inconclusive, with reason `"no user turns in reference transcript"`.

   The script is aikdm-internal. It is not a wire format and is not exposed to open-bbcd or the
   BO. It is the extension point for later step types (see Scope → Out).

2. **Executor.** `run_session` becomes: compile the script, then execute its steps in order. The
   step count is fixed at compile time, so the simulator's `stop` field, the `+4` cap and
   `_count_user_turns` are removed. For each step type:
   - **`UserStep(k)`** produces the user message for turn *k*, according to the user-turn mode
     (Scope → In → 3).
   - **`AgentStep(k)`** calls the target with the history built from the configured history
     mode (Scope → In → 4), plus user message *k*. It records the generated **turn span**: the
     assistant messages with their tool calls and results, ending in the final assistant text.
   - **`JudgeStep(k)`** runs the per-turn checkpoint (Scope → In → 5).

3. **User-turn mode** (`AIKDM_EVAL_USER_TURN_MODE`):
   - **`verbatim` (default).** User message *k* is `render_user_turn(step.ref_message)`:
     - string content is used as-is;
     - for content-block arrays, the `text` blocks are joined with `"\n\n"` in order;
     - other block types are omitted.

     No simulator LLM call is made. `render_user_turn` lives on the `UserStep` path, so the
     `client_context` spec can extend it in one place.
   - **`paraphrase` (opt-in).** The simulator LLM receives the reference transcript, the
     simulated history so far, and the explicit intent to send (`render_user_turn` of
     reference user turn *k*). It returns `{content}` only; the `stop` field is removed from
     its output schema. The rewritten prompt says:
     - always send turn *k*'s intent, even if the agent's last reply asked a question;
     - never answer the agent's question in place of the intent;
     - never add turns;
     - keep ids, numbers, dates and pasted JSON or documents verbatim;
     - change only the connective wording.

     An empty `content` falls back to the verbatim text for that turn.

4. **History mode** (`AIKDM_EVAL_HISTORY_MODE`). This decides what the target sees as turns
   1…*k-1* when it generates reply *k*:
   - **`simulated` (default).** The target sees the conversation as it actually happened in
     this run: earlier user messages plus the target's own earlier generated spans. This tests
     multi-turn coherence of the version under test.
   - **`reference` (opt-in).** The target sees the reference transcript's turns 1…*k-1*: the
     rendered reference user messages, plus the reference assistant messages with their tool
     calls and results replayed as canned history (Scenario's `agent("…")`). Only reply *k* is
     generated. Each turn is tested in isolation, so divergence early in the session cannot
     compound into later turns. User turns are always verbatim in this mode.
     `AIKDM_EVAL_HISTORY_MODE=reference` with `AIKDM_EVAL_USER_TURN_MODE=paraphrase` fails at
     `load_settings` with `ConfigError`.

   **One history renderer for both modes.** `to_target_messages(entries)` turns a list of
   aikdm transcript entries (user / assistant-with-`tool_calls` / assistant) into LiteLLM
   OpenAI-format messages:
   - an assistant entry with tool calls becomes an `assistant` message with
     `tool_calls: [{id, type: "function", function: {name, arguments: <json>}}]`, followed by
     one `tool` message per call carrying `tool_call_id` and the JSON result;
   - a missing result (`null`) is rendered as the JSON `null`;
   - ids are synthesized deterministically as `call_<turn>_<n>`.

   In `reference` mode, reference `InputMessage`s are first normalized into the same entry
   shape by `reference_entries(turns)`:
   - a user message becomes `render_user_turn(msg)`;
   - an assistant message's `content` is reduced to its `text` blocks joined with `"\n\n"`, and
     its `tool_use` blocks are dropped, because the export already hoists them into
     `tool_calls` with their results;
   - its `tool_calls` (`name`, `args`, `result`) become the entry's tool calls;
   - reference `role: tool` messages are skipped, because their results already arrived
     through `tool_calls[].result`, so they are never rendered twice.

   **Tool calls the bundle doesn't declare.** In `reference` history, a tool call is rendered as
   a structured tool call only if its `name` is among the current bundle's tools. Otherwise
   (the tool was removed or renamed, or the bundle has no tools), the call is rendered as plain
   assistant text:
   `[called tool <name> with <args json> → <result json>]`.
   This keeps the request valid for providers that reject tool history without matching tool
   definitions.

   `target_turn` stops mutating its caller's `conversation`. It returns the full generated span,
   intermediate tool-calling entries included, and the executor appends that span to the run
   transcript. This fixes root cause 5.

5. **Per-turn judge checkpoint.** `JudgeStep(k)` makes one judge call for turn *k*'s criteria.
   Its input:
   - `<context>`: the history the target saw for turn *k*, using the same history mode, so in
     `reference` mode the judge sees the reference history. Context only, not judged.
   - `<turn_under_test>`: user message *k* and the **whole generated span of turn *k***: every
     assistant message, its tool calls and results, and the final text. Criteria about tool use
     ("looks the order up by id") are judged on this span, not treated as context.
   - `<criteria>`: that turn's items only, in the order from Scope → In → 1.

   Messages generated after turn *k* are never in the input. The judge model runs at
   temperature 0, set through the judge `LlmAgent`'s `generate_content_config`.

6. **Inconclusive verdicts.** `Judgment` gains `inconclusive: bool = False`. An inconclusive
   judgment always has `passed=False`, so it counts as failed in `passed_criteria`,
   `total_criteria` and the score. The flag tells "the agent got it wrong" apart from "we could
   not judge it". The executor sets it, never the judge LLM, in these cases:
   - **Turn not reached** (`simulated` mode only). The target for turn *j < k* raised, or
     returned the tool-budget sentinel `"(target agent exceeded tool-call budget)"`.
     - The executor skips every later `UserStep`, `AgentStep` and `JudgeStep`.
     - Turn *j*'s own criteria are still judged on whatever span it produced. A raise that
       produced no assistant message makes those criteria inconclusive with reason
       `"turn <j> target error: <exception message>"`, and no judge call is made.
     - Criteria of later turns *k* are inconclusive with reason
       `"turn <k> not reached: turn <j> <cause>"`, where `<cause>` is `target error: <message>`
       or `exceeded tool-call budget`.
     - In `reference` mode, turns are independent: a failure at turn *j* affects only turn *j*.
   - **Judge failure.** The judge call for turn *k* raises, returns output that does not
     parse, or returns a different number of entries than the criteria it was sent. All of
     that turn's criteria are inconclusive with reason `"judge error: <message>"`; a count
     mismatch uses the message `"expected <n> judgments, got <m>"`. The other turns' judgments
     and the transcript are kept. The session is no longer zeroed by
     the orchestrator's catch-all `except`, which now only covers failures outside the
     executor, such as script compilation or tool-caller construction.
   - **Empty script**, as defined in Scope → In → 1.

7. **Result semantics.**
   - `Judgment.message_id` stays the reference assistant message id the criterion was attached
     to. It now really identifies the turn that was judged.
   - `Judgment.criterion` is the **input** criterion text, never the judge's echoed copy. The
     judge's entries are matched to criteria by position, after the count check in Scope → In → 6.
   - Judgments are listed in turn order, then in the criterion order from Scope → In → 1.
   - `ResultSession.transcript` holds, for each executed turn, user message *k* followed by the
     generated span *k*. In `reference` mode the canned history is not repeated in the
     transcript.
   - Session `score = passed / total` and the global score math are unchanged.
   - `aikdm_meta` gains `user_turn_mode` and `history_mode`.
   - `aikdm_meta.user_simulator_model` stays required and records the configured model even in
     `verbatim` mode, where it is not called. `load_settings` keeps requiring that model's
     provider key. Making it optional is not worth a contract change.

8. **Settings**, both on `Settings` in `config.py`:
   - `eval_user_turn_mode: Literal["verbatim", "paraphrase"] = "verbatim"`
     (env `AIKDM_EVAL_USER_TURN_MODE`);
   - `eval_history_mode: Literal["simulated", "reference"] = "simulated"`
     (env `AIKDM_EVAL_HISTORY_MODE`).

   Both apply to `aikdm evaluate` and to every eval run inside `aikdm train-agent`. Invalid
   values, or the invalid combination from Scope → In → 4, fail at `load_settings` with
   `ConfigError`.

9. **Training teacher skips inconclusive judgments.** `train/teacher.py` `_render_last_eval`
   omits judgments with `inconclusive=true` from the `<judgments>` block it sends to the
   teacher LLM. Inconclusive results are infrastructure outcomes (crashes, judge errors), not
   agent behaviour, and the teacher must not propose prompt patches for them. The `<score>`
   line is unchanged and still counts them as failed, the same as the promotion decision does.

10. **Unit tests**, with mocked LLMs and no network:
   - **Compile:**
     - 1, 2 and N user turns give the right `UserStep` / `AgentStep` / `JudgeStep` sequence;
     - a pre-first-user assistant message goes to turn 1;
     - criteria on intermediate tool-calling messages route to their turn;
     - unmapped ids go to the last turn with the prefixed reason;
     - criteria order is stable when the input criteria are shuffled;
     - an empty transcript gives an empty script and inconclusive criteria.
   - **Execute:**
     - a 1-user-turn reference makes exactly 1 target call;
     - N turns make N calls, in every mode combination;
     - in `paraphrase`, the simulator is called exactly N times and cannot change the step
       count;
     - an empty paraphrase falls back to verbatim;
     - when the agent's reply ends with a question, turn *k+1* still carries reference turn
       *k+1*'s intent (in `verbatim`, identical text).
   - **History:**
     - `to_target_messages` produces valid OpenAI tool-call / tool-result pairs;
     - in `simulated` mode, turn 2's target input contains turn 1's generated span with
       well-formed tool messages (regression test for root cause 5);
     - in `reference` mode, turn 2's target input contains reference turn 1's assistant
       messages and none of the generated ones;
     - `reference_entries` keeps only `text` blocks, skips `role: tool` messages, and renders a
       `null` result as JSON `null`;
     - a reference tool call whose tool is not in the bundle (and the no-tools bundle case)
       renders as plain assistant text;
     - `reference` + `paraphrase` raises `ConfigError`.
   - **Judge:**
     - turn 1 and turn 2 criteria go to separate judge calls;
     - turn 2's text is absent from turn 1's judge input;
     - turn *k*'s tool calls appear inside `<turn_under_test>`;
     - the judge agent is built with temperature 0.
   - **Inconclusive:**
     - a target exception at turn 1 of 2 in `simulated` mode makes both turns' criteria
       inconclusive with the specified reasons and makes no judge calls;
     - the same failure in `reference` mode still judges turn 2;
     - a judge exception on turn 2 keeps turn 1's judgments and makes turn 2's inconclusive;
     - a judge returning too few or too many entries makes that turn's criteria inconclusive,
       and `total_criteria` is unchanged;
     - `Judgment.criterion` is the input text even when the judge echoes it differently;
     - an unmapped criterion is judged and can pass;
     - `inconclusive` judgments count as failed in the score.
   - **Teacher:** `_render_last_eval` omits inconclusive judgments and keeps the `<score>` line.

11. **Noise measurement**, run manually and recorded in the implementation PR description.
    - Dataset: the consumer's reproduction setup, agent `customer-sparring` with dataset
      `customer-sparring / core` (10 sessions), Haiku 4.5 for every role, on a local open-bbcd.
      Its fixtures are available locally under `OpenBBC/.local-salescopilot/datasets/`. If that
      setup cannot be reproduced, any CLOSED dataset of at least 10 sessions with 1–2 user turns
      each is acceptable; name it in the PR.
    - Runs: 3 before the change, then 3 after with the defaults (`verbatim` + `simulated`) and 3
      with `verbatim` + `reference`.
    - Report: the per-run scores and the peak-to-peak spread, in percentage points of the
      [0, 1] score.

### Out of scope

- **Goal-driven free-running simulation** (Scenario's `description` plus `proceed()`, where the
  judge decides when to stop). Our datasets are recorded transcripts, not goals. Free-running is
  exactly the overrun this spec removes. A future step type can add it.
- **Deterministic code assertions** (Scenario's `state.has_tool_call(...)` functions). Criteria
  are free text authored in the BO. A structured assertion criterion type would need new
  `eval-input-v1` fields and BO UI, which is a C2 contract change. The step script leaves room
  for an `AssertStep`.
- **Record/replay caching of LLM calls** (Scenario's `cache_key`). We evaluate a *changed*
  agent, and caching the target would defeat the purpose.
- **Extra exploratory turns** (`allow_extra_turns`). Turns beyond the script have no scripted
  intent and no criteria.
- **A session-level rubric mode** (judging against the whole transcript). It is the behaviour
  being removed.
- **Fail-fast on a failed checkpoint** (Scenario stops at the first failed `judge()`). We need a
  graded score across all criteria, so every reached turn is judged.
- **Per-eval or per-session control** of the modes from open-bbcd or the BO. That would need
  contract fields and BO UI, which is C2. Do it only if aikdm-wide settings turn out to be too
  coarse.
- **A BO per-turn view and an inconclusive badge** in eval detail. The data
  (`Judgment.message_id`, `Judgment.inconclusive`) is now accurate. This is BO-only follow-up
  work.
- **`client_context`** itself, which has its own spec. This spec provides only the `UserStep`
  seam.
- **Multi-agent eval.** Versions with the agent tool still get `409` from export, and child
  transcripts are not replayed or judged.
- **Training promotion rules** (promoting only when better by more than the noise band, or
  averaging k runs). Revisit after the Scope → In → 11 numbers.
- **Changing target-model temperature.** The target should behave as it does in production.
- **Non-text user content blocks** (images, documents) in replay. They are dropped today too, so
  this is no regression.

## Contracts

- **API / DB / events:** none.
- **`eval-input-v1`** (open-bbcd `internal/eval/export.go` → aikdm `eval/schemas.py`):
  unchanged. aikdm now *uses* `InputCriterion.message_id`, message order and roles, and
  `InputMessage.tool_calls` (for `reference` history). All of these were already present.
- **`eval-result-v1`** (aikdm → `POST /evals/{id}/result`):
  - Additive `Judgment.inconclusive: bool` (default `false`; when `true`, `passed` is always
    `false`).
  - Additive `aikdm_meta.user_turn_mode: "verbatim" | "paraphrase"` and
    `aikdm_meta.history_mode: "simulated" | "reference"`.
  - `Judgment.message_id` is the same field with the same value, now accurate: it identifies
    the turn that was judged.
  - `Judgment.criterion` is always the input criterion text.
  - `ResultSession.transcript` contains at most N user turns (N = reference user turns), each
    followed by its generated span.

  open-bbcd persists `judgments` and `aikdm_meta` as opaque JSONB, and the BO ignores unknown
  judgment keys, so no open-bbcd change is needed.
- **aikdm configuration:** new envs `AIKDM_EVAL_USER_TURN_MODE` (default `verbatim`) and
  `AIKDM_EVAL_HISTORY_MODE` (default `simulated`). Invalid values or combinations fail at
  `load_settings` with `ConfigError`.

## Acceptance criteria

1. When no target failure occurs, a reference session with N user turns makes exactly N target
   calls and produces N simulated user turns, in every mode combination. A "target call" is one
   `target_turn` invocation, however many LiteLLM completions its tool loop makes. Covered by
   unit tests.
2. `run_session` executes a script compiled by `compile_script`. The number of steps is fixed
   before the first LLM call, and nothing at runtime can add or remove steps.
3. In `verbatim` mode, simulated user turn *k*'s text equals `render_user_turn` of reference user
   turn *k*, and the user-simulator model is never called. In `paraphrase` mode, the simulator's
   output schema has no `stop` field.
4. Each criterion is judged in a judge call whose `<turn_under_test>` is its own turn's full
   generated span, and whose input contains nothing generated after that turn. The judge runs
   at temperature 0. Covered by unit tests on the judge input and the agent config.
5. In `reference` history mode, the target input for turn *k* contains the reference turns
   1…*k-1*, with well-formed tool-call / tool-result pairs, and none of this run's earlier
   generated replies.
6. In `simulated` history mode, multi-turn sessions with tool use send well-formed OpenAI tool
   messages on later turns. Covered by a regression test for root cause 5.
7. `total_criteria` always equals the number of criterion items in the input session.
   - Not-reached, judge-error (including a judge count mismatch) and empty-script criteria are
     kept as `inconclusive=true, passed=false`, with the reasons defined in Scope → In → 1
     and 6.
   - Unmapped criteria are **judged** against the last turn. They can pass or fail and carry the
     prefixed reason from Scope → In → 1.
   - A judge error on one turn does not discard the other turns' judgments.
8. `aikdm train-agent` uses the new executor, so its baseline eval of the parent version is the
   same computation as a fresh `aikdm evaluate` of that version. The teacher prompt contains no
   inconclusive judgments (Scope → In → 9).
9. The noise measurement (Scope → In → 11) is run and recorded in the implementation PR. The ±3
   point target from Business value is a **target, not a merge gate**. If it is missed but the
   spread improves on the before-numbers, the PR merges, and the numbers feed the out-of-scope
   promotion-rule follow-up.
10. `uv run pytest` and `ruff` in `aikdm/` pass. The existing `test_train_orchestrator.py`
    passes unchanged.

## Risks & assumptions

- **Assumption: reference user turns are meaningful on their own.** In `simulated` +
  `verbatim`, turn *k* is sent even if the new agent's reply k-1 went somewhere else. A turn
  that only answers the old agent's question (e.g. "yes, the second one") can read oddly. Two
  modes cover this: `reference` history removes it completely, and `paraphrase` softens it.
- **Risk: `reference` mode can flatter a weak agent.** In `reference` mode the target never sees
  its own earlier mistakes, so multi-turn coherence goes untested. That is why it is opt-in and
  `aikdm_meta.history_mode` records it. Compare scores only within one mode.
- **Risk: criteria authors attached session-wide criteria to one message.** Under the old judge
  such a criterion could be satisfied anywhere in the session; now it is checked only against
  its own turn. Scores on existing datasets may move. This is the intended fix, but PLs should
  re-baseline after the upgrade. Call it out in the release note.
- **Risk: residual noise from the target model.** Target temperature is unchanged, so some
  run-to-run variance remains. `reference` mode and the promotion-rule follow-up are the next
  levers.
- **Risk: more judge calls.** One call per turn that has criteria instead of one per session.
  Sessions are 1–2 turns in practice, and each call's input is shorter, so total judge tokens
  stay about the same.
- **Risk: reference tool-call history is lossy.** The export keeps `name`, `args` and `result`,
  but not provider tool-call ids, so ids are synthesized. Replayed results are the stored
  results, which can be stale relative to a real backend. This is acceptable for history: they
  are what the reference agent actually saw.
- **Risk: reference history mentions tools the version under test lacks.** A new version may
  remove or rename tools, and Anthropic rejects tool history without matching tool
  definitions. Mitigation (Scope → In → 4): such calls are rendered as plain text. The target
  still sees what happened, but cannot be steered into calling a tool it no longer has.
