# Glossary

| Term                    | Definition                                                                                                                                                                                                                                                                                                                                                                            | Owning context                                                                                                                                                                             | Aliases                                  |          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | -------- |
| Agent                   | A named, versioned prompt-bundle-plus-wiring configuration that runs inside `open-bbcd`. Structural (endpoints, flows, capabilities) is frozen on the agent; prompts are editable per version. Linked-list versioning via `agents.parent_version_id`.                                                                                                                                 | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | —                                        |          |
| Agent version           | One node in an agent's version linked list. Owns editable prompts + version-scoped MCP attachments. Immutable once superseded.                                                                                                                                                                                                                                                        | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | version, bundle version                  |          |
| Capability              | Canonical term for a backend interface (endpoint, tool) the agent uses. Discovered from the frontend by `flow-map-compiler`, carried through `FlowMapConfig.Capabilities`, and exposed at runtime as tool calls to MCP backends.                                                                                                                                                      | [discovery](ddd/contexts/discovery.md), [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                 | resource (legacy)                        |          |
| Tool backend            | A row in `tool_backends` (migration 014), kind ∈ `{http_endpoint, mcp_client}`, with opaque `config` JSONB. `http_endpoint` = OpenBBC's built-in MCP-over-REST bridge (open-bbcd calls a plain REST endpoint and exposes it as an MCP tool). `mcp_client` = proxy to an existing MCP server. Managed via `/mcp` in the backoffice.                                                    | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | MCP backend, backend                     |          |
| MCP attachment          | Version-scoped row in `agent_version_mcp_backend` (migration 015) attaching an MCP backend to an agent version, with an editable `note` rendered into the prompt.                                                                                                                                                                                                                     | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | —                                        |          |
| Endpoint→backend wiring | Agent-scoped row in `agent_endpoint_backend` (migration 017) mapping a discovery endpoint id to a `tool_backends` row. Structural — every version of the same agent sees the same wiring for a given endpoint.                                                                                                                                                                        | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | agent wiring                             |          |
| `.flow-map/`            | Directory + zip produced by `flow-map-compiler` from a client frontend repo (schema v2): `AGENTS.md`, `APP.md`, `glossary.md`, `skills/<id>.md`, `flows/<id>.md`, `endpoints/<id>.md` (`proposed: true`). Uploaded via the wizard; stored inline on `agents.discovery_zip BYTEA` after migration 026.                                                                                 | [discovery](ddd/contexts/discovery.md)                                                                                                                                                     | flow-map, discovery zip                  |          |
| Bundle                  | Single YAML that aikdm emits and consumes: `metadata`, `main_prompt`, `capabilities[]`, `skills[]`, `external_actions[]`. Section structure declared in `aikdm/schemas/prompt-v1.yaml`.                                                                                                                                                                                               | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | prompt bundle, `bundle.yaml`             |          |
| Chat session            | Row in `chat_sessions`. One session per (agent version × user) in the backoffice test chat. Carries `backend_header_overrides` (migration 016) for outbound MCP calls; `locked_at` flips when the session is closed into a dataset version.                                                                                                                                           | [feedback-datasets](ddd/contexts/feedback-datasets.md)                                                                                                                                     | BO chat session                          |          |
| Feedback                | Row in `chat_message_feedback` attached to an `assistant`-role `chat_messages` row (repo-layer FK). Fields: `rating` ∈ `{up, down}`, `comment`, `expected_output`, `judge_criteria` (JSONB array, migration 021).                                                                                                                                                                     | [feedback-datasets](ddd/contexts/feedback-datasets.md)                                                                                                                                     | judge criteria                           |          |
| Dataset                 | Named collection of chat sessions with a two-state lifecycle: `DRAFT` (mutable, at most one per dataset) → `CLOSED` (immutable snapshot). Closing a draft seeds the next DRAFT with the closed version's sessions (cumulative, migration 020).                                                                                                                                        | [feedback-datasets](ddd/contexts/feedback-datasets.md)                                                                                                                                     | —                                        |          |
| Dataset version         | Row in `dataset_versions` with `status ∈ {DRAFT, CLOSED}`, `version_num`, `close_note`. A CLOSED version is what evals target.                                                                                                                                                                                                                                                        | [feedback-datasets](ddd/contexts/feedback-datasets.md)                                                                                                                                     | —                                        |          |
| Eval                    | Row in `evals`: one run of an agent version against a closed dataset version. States `PENDING → IN_PROGRESS → DONE                                                                                                                                                                                                                                                                    | FAILED`. Score = `sum(passed_criteria) / sum(total_criteria)` across all sessions. `mock_mcp_tools` toggles replay vs real MCP calls.                                                      | [evaluation](ddd/contexts/evaluation.md) | eval run |
| Eval session            | Row in `eval_sessions` (migration 022): per-simulated-session breakdown for an eval, with full `transcript` and per-criterion `judgments` JSONB.                                                                                                                                                                                                                                      | [evaluation](ddd/contexts/evaluation.md)                                                                                                                                                   | —                                        |          |
| Training session        | Row in `training_sessions` (migration 024): one automated hill-climb loop originating from an eval. States `PENDING → IN_PROGRESS → DONE                                                                                                                                                                                                                                              | FAILED`. On DONE, `new_version_id` points at a newly-created agent version.                                                                                                                | [training](ddd/contexts/training.md)     | —        |
| Teacher / judge loop    | Aikdm's hill-climb: teacher LLM proposes prompt-section patches, apply, run eval as reward, promote if candidate score is strictly greater than best. Early stop on `patience` consecutive non-improvements or perfect score.                                                                                                                                                         | [training](ddd/contexts/training.md)                                                                                                                                                       | hill-climb                               |          |
| Deployed session        | Row in `deployed_sessions`: production runtime session between the client frontend and a `DEPLOYED` agent version, over AG-UI/SSE. Scoped by `user_id` (trusted from request, not verified by `open-bbcd`).                                                                                                                                                                           | [deployed-runtime](ddd/contexts/deployed-runtime.md)                                                                                                                                       | —                                        |          |
| Header override         | Per-session, per-backend HTTP-header map merged into outbound MCP tool calls. Backoffice chat: `chat_sessions.backend_header_overrides` (migration 016, per-backend layout). Evals: flat `evals.header_overrides` (migration 023). Not yet supported on `deployed_sessions`.                                                                                                          | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | header pass-through                      |          |
| AG-UI                   | Protocol between the client frontend and `open-bbcd`, over Server-Sent Events. Event types: `RUN_STARTED`, `TEXT_MESSAGE_START/CONTENT/END`, `TOOL_CALL_START/ARGS/END`, `TURN_END`, `ERROR`.                                                                                                                                                                                         | [deployed-runtime](ddd/contexts/deployed-runtime.md)                                                                                                                                       | —                                        |          |
| MCP                     | Protocol between `open-bbcd` and client backends. Transports: SSE, Streamable HTTP. When a `tool_backends` row is `http_endpoint` kind, no MCP wire protocol is used with the backend — OpenBBC bridges REST as MCP inside the agent-facing surface.                                                                                                                                  | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | Model Context Protocol                   |          |
| MCP-over-REST bridge    | Runtime behaviour of `tool_backends.kind = http_endpoint`: `open-bbcd` calls a plain REST endpoint on the client backend and exposes the result to the agent as if it were an MCP tool. Removes the requirement that clients ship an MCP server.                                                                                                                                      | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | REST-to-MCP bridge, HTTP bridge          |          |
| Alpha drainer           | Scripted composition `process_pending_alphas.sh` → `generate_alpha.sh` → `aikdm generate-agent` + `seed_bundle.py`. Enumerates PENDING agent versions and transitions each `PENDING → READY` in a single Postgres transaction. Runs as a k8s CronJob (`cronjob-alphas.yaml`) or one-shot from an operator. Needs `DATABASE_URL` because `seed_bundle.py` writes directly to Postgres. | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | pending-alpha drainer                    |          |
| PENDING (agent version) | `agent_versions.status` value between `INITIALIZING` and `READY`, added in migration 025. Wizard Finalize transitions the root version `INITIALIZING → PENDING`; the alpha drainer transitions it to `READY`. Full state machine: `INITIALIZING, PENDING, DRAFT, TRAINING, READY, DEPLOYED`.                                                                                          | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | —                                        |          |
| Backoffice UI           | Server-rendered admin surface inside `open-bbcd` (`html/template` + htmx). Entrypoint `internal/handler/api.go:194`. No SPA.                                                                                                                                                                                                                                                          | [agent-lifecycle](ddd/contexts/agent-lifecycle.md), [feedback-datasets](ddd/contexts/feedback-datasets.md), [evaluation](ddd/contexts/evaluation.md), [training](ddd/contexts/training.md) | BO                                       |          |
| flow-map-compiler       | Claude Code plugin skill from `bbc-discovery/flow-map-compiler/`. Fully agent-driven — no script pipeline. Contract triple: `output-schemas.md` ↔ `lint-contract.md` ↔ `assets/templates/*.tmpl`.                                                                                                                                                                                     | [discovery](ddd/contexts/discovery.md)                                                                                                                                                     | discovery skill                          |          |
| aikdm                   | Python 3.12+ CLI, `uv` for deps. Three subcommands: `generate-agent`, `evaluate`, `train-agent`. Out-of-process, DB-unaware; talks REST to `open-bbcd`. Published to `ghcr.io/dacdigital/openbbc/aikdm`.                                                                                                                                                                              | [agent-lifecycle](ddd/contexts/agent-lifecycle.md), [evaluation](ddd/contexts/evaluation.md), [training](ddd/contexts/training.md)                                                         | —                                        |          |
| aikdm-runner            | Multi-layer image that packages bash + curl + tini + python 3.12 + uv + the `aikdm/` source + the top-level `scripts/` directory. Used by the Helm chart's three CronJobs (`alphas`, `evals`, `trainings`) to drain PENDING queues from an `open-bbcd` instance. Runs as uid 65532 (`runner`). Published to `ghcr.io/dacdigital/openbbc/aikdm-runner`.                                | [agent-lifecycle](ddd/contexts/agent-lifecycle.md), [evaluation](ddd/contexts/evaluation.md), [training](ddd/contexts/training.md)                                                         | drainer image                            |          |
| open-bbcd               | Go daemon: backoffice UI + REST API + agent runtime, all in one binary. Needs no local disk state (discovery zip lives in Postgres per migration 026); all persistence in Postgres. Subcommands `serve` (default), `migrate`, `healthcheck`. Published to `ghcr.io/dacdigital/openbbc/open-bbcd`.                                                                                     | [agent-lifecycle](ddd/contexts/agent-lifecycle.md)                                                                                                                                         | —                                        |          |
| Helm chart              | `deploy/helm/openbbc/` — k8s manifests shipping open-bbcd Deployment + Service + optional Ingress, optional in-cluster Postgres StatefulSet, and three CronJobs running the `aikdm-runner` image. Default image repositories point at `ghcr.io/dacdigital/openbbc/*`; only `image.tag` needs to be set at install time.                                                               | (cross-cutting)                                                                                                                                                                            | —                                        |          |
| Artifact                | User-visible file object exchanged inside a chat or deployed session: a document, image, audio, video, or any other MIME. Referenced from `chat_messages.content` / `deployed_messages.content` as a typed content block; bytes live in the configured artifact store, never in Postgres. Four legs: user upload, MCP tool output (unpacked from `ImageContent` / `EmbeddedResource`), agent-emitted, agent-to-tool argument.  | [artifacts](ddd/contexts/artifacts.md), [feedback-datasets](ddd/contexts/feedback-datasets.md), [deployed-runtime](ddd/contexts/deployed-runtime.md)                                       | file, upload, attachment (avoid — collides with MCP attachment) |          |
| Artifact store          | Deployer-provided blob backend that OpenBBC uploads artifact bytes to and reads them back from. Configured through the `artifact_stores` row (kind + opaque `config` JSONB) plus a global default selector. Parallel in shape to `tool_backends`: OpenBBC ships an adapter interface + one first-class kind, deployer picks the actual infrastructure.                                | [artifacts](ddd/contexts/artifacts.md)                                                                                                                                                     | blob store, object store                 |          |
| Artifact-store adapter  | Pluggable interface inside `open-bbcd` that wraps a concrete artifact store behind a stable put/get/delete/sign contract. First shipped kind: `s3_compatible` (works with AWS S3, MinIO, GCS-with-HMAC, R2, B2, and any S3-API endpoint). Adapter is selected by `artifact_stores.kind`; adapter config lives in `artifact_stores.config`. Framework parity with `tool_backends.kind`.  | [artifacts](ddd/contexts/artifacts.md)                                                                                                                                                     | storage adapter                          |          |
| Content block           | Typed element inside `chat_messages.content` / `deployed_messages.content` JSONB. Historically the column carried an opaque text blob; with artifact support the column holds an ordered list of typed blocks — at minimum `text` and `artifact_ref` (pointer to an `artifact_stores` row + store-local uri + MIME + optional size + hash). MCP `ImageContent` / `EmbeddedResource` tool-result payloads are normalised into `artifact_ref` blocks on ingest. | [artifacts](ddd/contexts/artifacts.md), [feedback-datasets](ddd/contexts/feedback-datasets.md), [deployed-runtime](ddd/contexts/deployed-runtime.md)                                       | message parts                            |          |
